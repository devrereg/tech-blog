> 마인드리퍼블릭에서 운영하는 서비스 **WENOA**의 **인플루언서 검색 최적화 ETL 파이프라인** 구축 기록입니다. 유튜브·인스타그램·틱톡 채널을 대량으로 수집·가공·색인하는 파이프라인을 만들고, 기존 텍스트 매칭 기반 검색을 **멀티모달 임베딩 기반 의미(Semantic) 검색**으로 전환해 검색어·카테고리와 채널의 실제 연관성을 끌어올렸습니다.

## 프로젝트 개요

- **회사 / 서비스**: 마인드리퍼블릭 / WENOA
- **프로젝트명**: 인플루언서 검색 최적화를 위한 ETL 파이프라인 구축
- **일정**: 2025.07 (3개월)
- **기술 스택**: AWS EC2 (`t3a.medium`) · Spring Boot 3 (Kotlin) · FastAPI · GPT-4o-mini · 임베딩 모델(`BAAI/bge-m3`) · Elasticsearch · YouTube Data API v3 · Web Crawling (Instagram · YouTube · TikTok) · Multi-modal Embedding

**설계 기준**

- 1일 수집 키워드 수 1,000개
- 키워드 1개당 채널 50개 추출 → **1일 최대 5만 채널** 수집·가공·저장
- 검색어·카테고리와 채널의 의미적 연관성을 반영한 랭킹 제공

## 아키텍처

![WENOA 인플루언서 검색 최적화 ETL 파이프라인 아키텍처(2025.07) 다이어그램. 수집(Extract) 단계에서는 EC2 t3a.medium 위의 배치 스케줄러(Spring Boot 3 + Kotlin)가 1일 1,000개 키워드 소스를 입력받아, 키워드마다 YouTube Data API v3와 Web Crawling(Instagram·YouTube·TikTok)으로 후보 채널을 조회하고 상위 50개를 추출해 1일 최대 5만 채널을 수집한 뒤, 채널 설명·인기 게시물 이미지 등 원본 데이터를 저장한다. 가공(Transform) 단계에서는 채널 Description과 인기 게시물의 이미지·텍스트를 GPT-4o-mini로 요약해 하나의 텍스트로 정규화하고, 이를 로컬 임베딩 모델 BAAI/bge-m3로 임베딩 벡터로 변환한다. 별도로 DB에 사전 저장된 카테고리별 대표 벡터(category.vector)와 채널 벡터의 코사인 유사도, 그리고 채널 텍스트 내 카테고리 키워드 출현 횟수를 선형 결합해 카테고리 가중치를 산출하고 가중치 기반 카테고리 매핑을 만든다. 색인(Load) 단계에서는 임베딩 벡터 값과 카테고리 메타데이터를 Elasticsearch의 벡터 필드 인덱스에 색인한다. 검색 단계에서는 사용자가 Semantic Search API(Spring Boot)에 검색어를 보내면, API가 검색어를 같은 임베딩 공간의 벡터로 변환해 Elasticsearch에서 벡터 유사도 검색을 수행하고 카테고리 매핑을 결합해 정렬된 인플루언서 결과를 반환한다](/assets/img/posts/mindrepublic-wenoa-influencer-search/wenoa_influencer_etl_pipeline.drawio.png)

*WENOA 인플루언서 검색 최적화 ETL 파이프라인 (2025.07) — Extract(배치 스케줄러가 키워드 → YouTube Data API·크롤링으로 일 5만 채널 + 인기 게시물 수집) → Transform(GPT-4o-mini 요약 → 로컬 `bge-m3` 임베딩, 사전 저장 `category.vector`와의 코사인 유사도·키워드 카운트를 선형 결합한 카테고리 가중치 매핑) → Load(Elasticsearch 벡터 필드 + 카테고리 메타데이터 색인) → Semantic Search API가 검색어를 벡터로 변환해 유사도 검색.*

전체 흐름은 **수집(Extract) → 가공(Transform) → 색인(Load) → 의미 검색**의 4단계로 나뉜다.

1. **수집(Extract)** — EC2(`t3a.medium`) 위의 배치 스케줄러(Spring Boot 3 / Kotlin)가 일 1,000개 키워드를 소비하며, 키워드마다 YouTube Data API v3와 웹 크롤링(Instagram·YouTube·TikTok)으로 후보 채널을 조회해 상위 50개를 추출한다(일 최대 5만 채널). 채널 설명, 인기 게시물 이미지 등 원본 데이터를 저장한다.
2. **가공(Transform)** — 채널 `Description`과 인기 게시물의 이미지·텍스트를 **GPT-4o-mini로 요약**해 채널 하나를 대표하는 텍스트로 정규화하고, 이를 로컬 임베딩 모델 `BAAI/bge-m3`(FastAPI)로 **임베딩 벡터**로 변환한다. 별도로 **카테고리별 대표 벡터와의 코사인 유사도 + 카테고리 키워드 출현 횟수**를 조합해 카테고리 가중치를 산출하고, 가중치 기반 카테고리 매핑을 만든다.
3. **색인(Load)** — 임베딩 벡터와 카테고리 메타데이터를 Elasticsearch의 **벡터 필드 인덱스**에 색인한다.
4. **의미 검색** — 사용자가 Semantic Search API(Spring Boot)에 검색어를 보내면, API가 검색어를 같은 임베딩 공간의 벡터로 변환해 Elasticsearch에서 **벡터 유사도 검색**을 수행하고, 가중치 기반 카테고리 매핑과 결합해 인플루언서를 정렬해 반환한다.

## 문제

### 텍스트 기반 검색으로 인한 낮은 검색 연관성

기존 인플루언서 검색은 **채널 텍스트(제목·description 등)와 검색어의 문자열 매칭** 방식이었다.

- 검색어·카테고리와 **실제 연관성이 낮은 채널**이 검색 결과 상위에 노출됐다. 단어만 겹치고 채널의 실제 주제는 다른 경우가 걸러지지 않았다.
- 같은 의미라도 표현이 다르면(동의어·유사 개념·다른 언어) 매칭되지 않아, 관련 채널이 검색 결과에서 누락됐다.
- 채널의 성격은 프로필 텍스트만으로 드러나지 않고 실제 올리는 콘텐츠(이미지·영상)에서 드러나는데, 텍스트 매칭은 이 정보를 전혀 활용하지 못했다.

## 해결

### 멀티모달 임베딩 + 가중치 기반 카테고리 매핑으로 의미 검색 전환

채널을 **프로필 텍스트와 실제 게시 콘텐츠(이미지)를 함께 반영한 벡터**로 표현하고, 검색을 벡터 유사도 기반으로 바꿨다.

- **멀티모달 정보의 텍스트 정규화** — 각 채널의 `Description`과 **인기 게시물의 이미지·텍스트**를 GPT-4o-mini로 요약해, 채널 하나를 대표하는 **한 덩어리의 텍스트**로 정규화했다. 프로필 문구뿐 아니라 실제 올리는 콘텐츠의 특징까지 이 텍스트에 담긴다.
- **임베딩 생성** — 정규화한 텍스트를 다국어에 강한 로컬 임베딩 모델 `BAAI/bge-m3`로 임베딩해 채널 벡터를 만들었다. 임베딩 추론은 FastAPI 서버가 담당한다(요약은 GPT-4o-mini, 임베딩은 로컬 모델로 역할 분리).
- **가중치 기반 카테고리 매핑** — 채널을 단일 카테고리로 못 박는 대신, 여러 카테고리에 대한 **연관도(가중치)를 산출**해 매핑으로 저장했다. DB에 **카테고리별 대표 벡터(`category.vector`)를 사전 저장**해 두고, 채널 벡터와 각 `category.vector`의 **코사인 유사도**, 그리고 **채널 텍스트 내 카테고리 키워드 출현 횟수**를 **선형 결합**해 카테고리별 가중치를 매긴다. 카테고리 검색 시 이 가중치가 랭킹에 반영된다.
- **벡터 기반 의미 검색** — 임베딩 벡터와 카테고리 메타데이터를 Elasticsearch **벡터 필드 인덱스**에 색인하고, 사용자 검색어를 같은 공간의 벡터로 변환해 **유사도 검색**을 수행한다. 벡터 유사도 점수와 가중치 기반 카테고리 매핑 점수를 결합해 최종 정렬한다. 검색 진입점은 Semantic Search API(Spring Boot)다.
- **ETL 파이프라인화** — 수집(배치 스케줄러, Spring Boot 3 / Kotlin) → 가공(GPT-4o-mini · FastAPI 임베딩) → 색인(Elasticsearch) 단계를 파이프라인으로 분리해, 일 1,000 키워드 · 최대 5만 채널 규모의 수집·가공·색인이 매일 자동으로 돌도록 구성했다.

## 결과

- 문자열 매칭이 놓치던 **동의어·유사 개념·다국어 표현**까지 의미 기반으로 매칭되어, 검색어·카테고리 기반 인플루언서 검색 결과의 **연관성과 정확도가 개선**됐다.
- 프로필 텍스트뿐 아니라 **실제 콘텐츠(이미지·텍스트)**를 반영한 임베딩으로, 채널의 실제 성격에 맞는 검색 결과를 제공하게 됐다.
- 일 1,000 키워드 · 최대 5만 채널을 매일 수집·가공·색인하는 **ETL 파이프라인**을 갖춰, 검색 대상 인플루언서 풀을 지속적으로 확장·갱신할 수 있게 됐다.
