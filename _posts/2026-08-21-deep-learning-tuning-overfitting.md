## 1. 신경망을 왜 깊게 쌓는가 {#why-deep}

이미지를 인식하는 신경망을 층 하나로만 쌓으면, 모서리(edge)나 색상 같은 아주 기본적인 특징 정도만 감지할 수 있습니다. 층 하나가 가진 표현력 자체가 제한적이기 때문입니다.

반면 층을 깊게 쌓으면 이야기가 달라집니다. 기본 특징(모서리, 색상)들을 조합해 눈·코·입 같은 좀 더 복잡한 형태를 인식하고, 그 형태들을 다시 조합해 "사람 얼굴 전체"라는 고차원적인 개념까지 인식할 수 있습니다.

```
1층: 점, 모서리, 색깔        (저수준 특징)
   ↓
2층: 눈, 코, 입 모양          (중간 수준 특징)
   ↓
3층: 얼굴 전체                (고차원 개념)
```

AlexNet 이후 **VGG-19**(19개 층), **ResNet**(최대 152개 층)처럼 층을 계속 쌓으려는 시도가 이어진 이유가 여기에 있습니다. 다만 층을 무작정 깊게 쌓으면 좋기만 한 게 아니라, 학습이 어려워지거나(경사 전달 지연·손실) 과적합 위험도 함께 커집니다. 이 글에서 다룰 배치 정규화·드롭아웃 같은 기법들이 필요한 이유가 바로 여기에 있습니다.

## 2. CNN 아키텍처 설계 {#cnn-architecture}

[지난 글]({% post_url 2026-08-20-cnn-image-classification %})과 동일하게 CIFAR-10(10개 클래스, 32×32 컬러 이미지)을 다루되, 이번에는 **합성곱(Convolution) 층 6개 + 풀링(Pooling) 층 3개**로 훨씬 깊게 쌓은 CNN을 사용합니다. 핵심 설계 원칙은 다음과 같습니다.

> **풀링으로 이미지 크기가 절반씩 줄어들 때마다, 채널 수를 2배씩 늘린다.**

공간 정보(이미지 크기)는 줄이는 대신, 채널 수(특징 맵의 개수)를 늘려서 정보 손실을 보완하는 전략입니다. "공간 정보는 압축하고, 대신 학습하는 특징의 종류는 더 다양하게 가져가겠다"는 트레이드오프인 셈입니다.

![6개 Conv + 3개 Pool로 구성된 CNN 아키텍처](/assets/img/posts/deep-learning-tuning-overfitting/01_architecture.svg)

| 블록 | 구성 | 채널 수 | 역할 |
|---|---|---|---|
| 1단계 | conv1-2 + pool1 | 32채널 | 첫 번째 특징 추출 (edge, 색상 등 저수준) |
| 2단계 | conv3-4 + pool2 | 64채널 | 중간 특징 학습 |
| 3단계 | conv5-6 + pool3 | 128채널 | 고차원 특징 인식 |

즉 **"합성곱 2개(특징 추출) → 풀링 1개(크기 축소)"** 패턴을 3번 반복하면서, 크기는 점점 줄이고 채널(특징의 깊이)은 점점 늘려가는 구조입니다.

## 3. 최적화 함수: SGD, Momentum, Adam {#optimizers}

**최적화 함수(Optimizer)**는 딥러닝 모델을 학습시키는 엔진과 같습니다. 손실 함수가 "가장 낮은 손실 값"이라는 목적지를 알려주는 내비게이션이라면, 최적화 함수는 그 안내에 따라 경사(gradient) 정보를 보고 파라미터를 조금씩 조정하며 목적지로 나아가는 역할을 합니다.

![최적화 함수별 손실 표면 위 이동 경로 (개념도)](/assets/img/posts/deep-learning-tuning-overfitting/02_optimizers.svg)

### SGD (확률적 경사하강법)

가장 기본적인 최적화 방식입니다.

$$W \leftarrow W - \eta \cdot \nabla W$$

- $W$: 가중치, $\eta$(에타): 학습률, $\nabla W$: 경사(gradient)
- "경사가 가리키는 반대 방향으로, 학습률만큼 조금씩 이동한다"는 뜻입니다.
- 직관적이지만 비효율적으로 움직이거나 지역 최솟값(local minimum)에 갇힐 위험이 있습니다.

### Momentum

SGD에 **관성** 개념을 추가한 버전입니다. 과거에 이동하던 경사 방향을 기억해서 현재 경사와 합쳐 이동합니다. 언덕을 굴러 내려가는 공처럼, 관성이 붙어 더 빠르고 부드럽게 이동합니다.

```
v ← momentum × v_이전 + 학습률 × 현재_경사
W ← W - v
```

`momentum=0.9`는 **이전까지 쌓아온 속도(관성)를 90% 반영**하겠다는 뜻입니다. 값이 클수록(1에 가까울수록) 관성이 강해지고, `momentum=0`이면 순수 SGD와 동일해집니다. 실무에서는 `0.8~0.99` 사이 값을, 보통 `0.9`를 관행적으로 많이 씁니다.

장점: 빠른 수렴, 지그재그 진동 완화, 얕은 지역 최솟값 탈출.

### Adam

현재 가장 널리 쓰이는 최적화 함수로, Momentum의 장점과 학습률 자동 조정 알고리즘(RMSProp 계열)의 장점을 결합했습니다. 파라미터마다 학습률을 다르게 자동 조정해주기 때문에, 별도의 세밀한 튜닝 없이도 안정적인 성능을 보여줍니다.

```
SGD (기본) → Momentum (관성 추가) → Adam (자동 조정까지 결합)
```

### 코드로 구현하기

```python
# SGD 기본 구현 (원리 이해용 - 실무에서는 잘 안 씀)
lr = 0.001
# 경사를 기반으로 파라미터 갱신
W.data -= lr * W.grad.data
B.data -= lr * B.grad.data
```

```python
# Momentum과 Adam (실무 - PyTorch 라이브러리 활용)
# Momentum
optimizer = optim.SGD(net_params, lr=lr, momentum=0.9)

# Adam
optimizer = optim.Adam(net_params)
```

첫 번째 코드(SGD 원리 구현)는 원리를 이해하기 위한 코드이고, 두 번째 코드(Momentum, Adam)는 실무에서 쓰는 라이브러리 활용 코드입니다. 실무에서는 특별한 이유가 없다면 보통 **Adam을 기본 선택지**로 많이 사용합니다.

## 4. 과적합(Overfitting)이란 무엇인가 {#what-is-overfitting}

**과적합**은 모델이 훈련 데이터에 너무 익숙해진 나머지, 정작 새로운 데이터(검증/시험 데이터)에서는 성능이 떨어지는 현상입니다. 핵심 징후는 **훈련 손실은 계속 줄어드는데, 검증 손실은 어느 시점부터 오히려 늘어난다**는 점입니다.

![과적합(Overfitting)의 전형적인 학습 곡선](/assets/img/posts/deep-learning-tuning-overfitting/03_overfitting_curve.svg)

과적합은 보통 3단계로 진행됩니다.

1. **초기 단계**: 훈련·검증 손실이 모두 감소합니다. 모델이 아직 데이터의 일반적인 패턴을 배우는 중인 건강한 상태입니다.
2. **최적점**: 검증 손실이 최솟값에 도달하는 지점입니다. 이론적으로 학습을 멈추기에 가장 이상적인 시점입니다.
3. **과학습(과적합) 발생**: 훈련 손실은 계속 감소하지만, 검증 손실은 오히려 증가합니다. 모델이 훈련 데이터의 노이즈나 특이 패턴까지 통째로 "암기"해버린 상태입니다.

> **비유**: 시험 준비할 때 기출문제만 통째로 외운 학생과 비슷합니다. 기출문제(훈련 데이터)는 완벽하게 맞히지만, 조금만 응용된 새로운 문제(검증 데이터)가 나오면 헤매는 상황이죠. 진짜 원리를 이해한 게 아니라 암기만 했기 때문입니다.

## 5. 과적합 대응 3대 기법 {#three-techniques}

과적합을 막는 방법은 여러 가지지만, 이 글에서는 접근 방식이 서로 다른 세 가지 대표 기법을 함께 사용합니다.

![과적합을 막는 세 가지 접근: 드롭아웃 · 배치 정규화 · 데이터 증강](/assets/img/posts/deep-learning-tuning-overfitting/04_techniques.svg)

### 5-1. 드롭아웃 (Dropout)

학습 과정에서 신경망 뉴런 중 일부를 무작위로 비활성화하는 기법입니다. 매번 학습할 때마다 다른 뉴런이 랜덤하게 꺼지기 때문에, 네트워크가 특정 뉴런 하나에만 과도하게 의존하는 것을 막습니다. 결과적으로 특정 패턴을 "암기"하는 대신 더 일반화된(robust) 특징을 학습하게 됩니다.

**훈련 모드와 평가 모드에서 다르게 동작**한다는 점이 중요합니다.

```python
# 훈련 모드: 50% 확률로 뉴런 비활성화
dropout.train()
# 출력: [-0.0000, 0.2407, -0.0000, -0.4808, ...]

# 평가 모드: 모든 뉴런 사용, 입력=출력
dropout.eval()
# 출력: [-0.1115, 0.1204, -0.3696, -0.2404, ...]
```

- **훈련 모드**: 50% 확률로 값을 0으로 꺼버리고, **살아남은 값은 2배로 스케일링**합니다(Inverted Dropout 방식). 뉴런 절반이 꺼지면 출력의 총합이 절반으로 줄어드는데, 살아남은 값을 미리 `1 ÷ 0.5 = 2`배 해줌으로써 전체 평균을 원래 수준으로 맞춰주는 것입니다.
- **평가 모드**: 드롭아웃이 아예 적용되지 않습니다. 실제 예측 단계에서는 모델이 가진 모든 뉴런을 다 써야 일관되고 안정적인 결과를 낼 수 있기 때문입니다.

### 5-2. 배치 정규화 (Batch Normalization)

각 미니배치 단위로 데이터의 평균을 0, 분산을 1로 정규화해서 다음 층으로 전달하는 기법입니다. 데이터 분포를 안정시켜 학습 효율을 높이고 과적합을 억제합니다.

**가장 표준적인 배치 위치는 "합성곱 연산 직후, 활성화 함수 직전"** — 즉 `Conv → BatchNorm → ReLU` 순서입니다.

- **Conv 직후**: 합성곱은 값의 스케일을 크게 바꿔놓는 연산입니다. 이렇게 흐트러진 직후 BatchNorm으로 분포를 다시 안정시킵니다.
- **ReLU 직전**: ReLU는 0보다 작은 값을 전부 0으로 만들어버립니다. 분포가 한쪽으로 치우친 상태에서 ReLU를 통과하면 정보 대부분이 손실될 수 있으므로, 통과 직전 평균 0·분산 1로 맞춰 정보 손실을 최소화합니다.

**내부 동작 원리**는 다음 수식으로 표현됩니다.

$$y = \frac{x - E[x]}{\sqrt{Var[x] + \epsilon}} \cdot \gamma + \beta$$

- 분자(`x - E[x]`): 평균을 0으로 맞추는 부분
- 분모(`√(Var[x] + ε)`): 분산을 1로 맞추는 부분. `ε`은 분모가 0이 되는 것을 막는 안전 장치
- `· γ + β`: 그냥 평균 0·분산 1로 고정하면 모델의 표현력이 떨어질 수 있으므로, **학습 가능한 파라미터 γ(스케일)와 β(이동)**를 두어 모델이 스스로 적절한 크기와 위치로 재조정할 여지를 남깁니다.

훈련 중에는 이와 별도로 지수 이동 평균(exponential moving average) 방식으로 `running_mean`과 `running_var`를 계속 업데이트합니다. 평가 시에는 현재 배치의 통계 대신, 훈련 중 축적된 이 값들을 사용해 **항상 결정론적으로(deterministic)** 동일한 결과를 냅니다.

```python
self.bn1 = nn.BatchNorm2d(32)
self.bn2 = nn.BatchNorm2d(32)
self.bn3 = nn.BatchNorm2d(64)
# ...
self.features = nn.Sequential(
    self.conv1, self.bn1, self.relu,
    self.conv2, self.bn2, self.relu, self.maxpool,
    self.dropout1,
    # ...
)
```

> ⚠️ **주의**: 채널 수가 같더라도 반드시 별개의 BatchNorm 인스턴스를 생성해야 합니다. BatchNorm은 단순 계산식이 아니라 학습 가능한 파라미터(γ, β)와 내부 상태(`running_mean`, `running_var`)를 가진 **"상태가 있는(stateful)" 레이어**이기 때문입니다. 하나의 인스턴스를 여러 위치에서 재사용하면, 서로 다른 위치의 서로 다른 데이터 분포가 같은 파라미터를 공유하게 되어 학습이 제대로 이루어지지 않습니다.

### 5-3. 데이터 증강 (Data Augmentation)

가지고 있는 데이터를 인위적으로 변형해서 양을 늘리는 방법입니다.

> **비유**: 아이에게 '고양이'를 가르칠 때, 완벽한 정면 사진 한 장만 보여주지 않는 것과 같습니다. 옆모습, 가려진 모습, 다른 조명 등 다양한 모습을 보여주어야 "고양이란 무엇인가"라는 본질을 제대로 학습할 수 있습니다.

- **RandomHorizontalFlip**: 이미지를 무작위로 좌우 반전합니다. 객체의 좌우 방향이 바뀌어도 의미가 변하지 않는 데이터에서 효과적입니다. (단, 숫자 "6"과 "9"처럼 방향이 곧 의미인 데이터에는 주의가 필요합니다.)
- **RandomErasing**: 이미지의 특정 사각 영역을 무작위로 지웁니다. 모델이 일부 정보만으로 전체를 유추하도록 훈련시켜, 특정 부위 하나에만 과도하게 의존하는 것을 방지합니다.

```python
transform_train = transforms.Compose([
    transforms.RandomHorizontalFlip(p=0.5),  # 50% 확률로 좌우 반전
    transforms.ToTensor(),
    transforms.Normalize(0.5, 0.5),
    transforms.RandomErasing(p=0.5, scale=(0.02, 0.33), ratio=(0.3, 3.3),
                              value=0, inplace=False)
])
```

- `scale=(0.02, 0.33)`: 지워지는 영역이 전체 면적의 2%~33% 사이에서 무작위로 결정됩니다.
- `ratio=(0.3, 3.3)`: 지워지는 사각형의 가로세로 비율 범위입니다.
- 새로운 `transform`을 정의하고 이를 사용하는 `DataLoader`만 새로 만들면, **기존 모델 코드는 전혀 수정하지 않고도** 데이터 증강이 적용된 훈련을 바로 시작할 수 있습니다.

**세 기법의 접근 방식 비교**

| 기법 | 접근 방식 | 작동 위치 |
|---|---|---|
| Dropout | 네트워크(뉴런) 자체를 무작위로 단순화 | 네트워크 내부 |
| BatchNorm | 각 층 사이 데이터 분포를 안정화 | 레이어 사이 |
| Data Augmentation | 입력 데이터 자체의 다양성을 확장 | 입력 단계 |

모델 단순화 + 학습 안정화 + 데이터 다양화, 세 방향에서 동시에 과적합을 방지하는 조합입니다.

## 6. `model.train()` / `model.eval()`을 꼭 챙겨야 하는 이유 {#train-eval-mode}

드롭아웃과 배치 정규화는 공통적으로 **훈련할 때와 예측할 때 다르게 동작하는 레이어**입니다. 이 동작을 스위칭해주는 것이 `.train()` / `.eval()` 호출입니다.

| | 훈련 모드 (`.train()`) | 평가 모드 (`.eval()`) |
|---|---|---|
| 드롭아웃 | 뉴런 일부 무작위 비활성화 | 모든 뉴런 사용 |
| 배치 정규화 | 현재 배치 통계로 정규화 + `running_mean/var` 갱신 | 저장된 `running_mean/var`로 정규화 |

이 함수들은 모델 내 특정 레이어의 동작 방식을 제어하므로, **각 루프 시작 전 반드시 명시적으로 호출**해야 합니다.

```python
for epoch in range(epochs):
    model.train()   # 학습 루프 시작 전 반드시 호출
    for batch in train_loader:
        ...  # 학습

    model.eval()     # 검증 루프 시작 전 반드시 호출
    with torch.no_grad():
        for batch in val_loader:
            ...  # 검증
```

`model.eval()`을 깜빡하고 검증을 돌리면 드롭아웃이 여전히 랜덤하게 뉴런을 꺼버리고, 배치 정규화는 미니배치 통계를 사용해버려서 **검증 결과가 들쭉날쭉해지고 신뢰할 수 없게** 됩니다. 실제로 "내 모델 성능이 왜 이렇게 불안정하지?"라는 문제의 상당수가 이 실수에서 비롯됩니다.

## 7. 실험 결과와 오답 분석 {#results}

세 기법을 하나씩 더해가며 실험한 결과, 정확도가 꾸준히 개선됐습니다.

![과적합 대응 기법 적용에 따른 검증 정확도 변화](/assets/img/posts/deep-learning-tuning-overfitting/05_accuracy_results.svg)

- **기본 CNN (SGD only)**: 층은 깊게 쌓았지만 초반 3에폭까지 정확도가 10%(랜덤 수준)에 머물렀습니다. 층이 깊어 경사 신호가 입력층까지 전달되는 데 시간이 걸린 것이 원인이며, 50에폭 학습 후 최종 정확도 **70%**를 기록했습니다. 다만 40에폭 근처에서 검증 손실이 반등하는 과적합 조짐이 관찰됐습니다.
- **+ Dropout + BatchNorm**: 학습이 훨씬 안정적으로 진행되며 정확도가 크게 개선됐습니다. (**87%**)
- **+ Data Augmentation**: 100에폭까지 학습을 늘렸음에도 훈련·검증 손실 곡선이 훨씬 가깝게 붙어 함께 감소하고, 최종 정확도 **89%**에 도달했습니다.

> 핵심 메시지: **모델 구조 자체는 하나도 건드리지 않고, 데이터를 다양하게 보여주는 것만으로도 성능이 개선**됩니다.

### 개별 예측 결과 확인

검증 데이터 처음 50개 이미지에 대해 예측해본 결과, 50개 중 3개만 틀려 **약 93%**의 정확도를 보였습니다. 오분류 사례로는 `dog↔deer`, `bird↔cat`, `car↔truck`처럼 **생김새가 비슷한 카테고리끼리 혼동**하는 경향을 보였는데, 이는 모델이 완전히 무작위로 틀린 게 아니라 나름 합리적인 방식으로 특징을 학습했다는 신호이기도 합니다.

### 소프트맥스로 오분류 확률 들여다보기

`car`를 `truck`으로 잘못 예측한 사례를 소프트맥스 함수로 분석해보면:

```python
probs = torch.softmax(output, dim=1)
probs_np = probs.data.to('cpu').numpy()[0]
```

| 클래스 | 확률 |
|---|---|
| truck | 77.75% |
| car | 22.21% |
| ship | 0.04% |
| 기타 | 0.00% |

모델이 완전히 엉뚱하게 예측한 게 아니라 **"truck 77.8% vs car 22.2%"로 두 후보 사이에서 고민한 흔적**이 보입니다. 정답인 car가 확률 2위로 꽤 높게 잡힌 것이죠. 이처럼 **오분류의 확신 정도(확률 분포)를 확인하는 것**은 모델을 디버깅하고 신뢰도를 판단하는 데 중요한 실무 기법입니다. 만약 `truck: 99.9%`처럼 극단적으로 틀렸다면 모델이 심각하게 잘못 학습됐다는 신호로 봐야 하지만, 지금처럼 비등하게 틀렸다면 애매한 이미지 때문에 어쩔 수 없이 발생한 실수로 이해할 수 있습니다.

## 8. 더 알아두면 좋은 개념 (보너스) {#bonus}

이 글에서 다룬 세 기법 외에도, 실무에서 튜닝/과적합 대응을 할 때 함께 알아두면 유용한 개념들을 추가로 정리합니다.

### 8-1. Early Stopping (조기 종료)

검증 손실이 더 이상 개선되지 않는 시점(4장의 "최적점")을 자동으로 감지해서 학습을 멈추는 기법입니다. 일정 에폭(patience) 동안 검증 손실이 개선되지 않으면 학습을 중단하고, 그 시점의 가중치를 최종 모델로 채택합니다. 과적합 구간까지 학습을 진행하지 않도록 막아주는 가장 직접적인 방법입니다.

### 8-2. 가중치 감쇠 (Weight Decay / L2 정규화)

손실 함수에 가중치 크기에 대한 페널티 항을 추가해서, 모델이 특정 가중치 값을 과도하게 키우지 못하도록 제한하는 기법입니다.

$$Loss_{total} = Loss_{original} + \lambda \sum W^2$$

PyTorch에서는 옵티마이저 생성 시 `weight_decay` 인자로 간단히 적용할 수 있습니다.

```python
optimizer = optim.Adam(net_params, lr=0.001, weight_decay=1e-4)
```

드롭아웃, 배치 정규화, 데이터 증강과 함께 자주 병행되는 정규화 기법입니다.

### 8-3. 학습률 스케줄링 (Learning Rate Scheduler)

학습이 진행됨에 따라 학습률을 점차 줄여가는 기법입니다. 초반에는 큰 보폭으로 빠르게 탐색하고, 후반에는 보폭을 줄여 최적점 근처에서 세밀하게 수렴하도록 돕습니다.

```python
scheduler = optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=50)
# 매 에폭 끝에서
scheduler.step()
```

대표적으로 `StepLR`, `CosineAnnealingLR`, `ReduceLROnPlateau`(검증 손실이 정체될 때 학습률을 낮춤) 등이 있습니다.

### 8-4. 기울기 소실/폭발 문제와 가중치 초기화

층이 깊어질수록 역전파 과정에서 경사(gradient)가 너무 작아지거나(소실) 너무 커지는(폭발) 문제가 발생할 수 있습니다. 7장에서 언급한 "초반 3에폭 정확도 10%" 현상도 이와 관련이 있습니다. 이를 완화하기 위한 대표적인 방법이 **He 초기화**(ReLU 계열 활성화 함수에 적합)나 **Xavier 초기화**처럼 층의 입출력 크기를 고려해 가중치의 초기값 분포를 세심하게 설정하는 것입니다.

```python
nn.init.kaiming_normal_(conv_layer.weight, nonlinearity='relu')  # He 초기화
```

### 8-5. 레이어 정규화 계열 (Layer/Group/Instance Normalization)

배치 정규화는 미니배치 단위로 통계를 계산하기 때문에 배치 크기가 아주 작으면(예: 1~2) 통계가 불안정해지는 단점이 있습니다. 이런 경우를 위해 배치가 아닌 다른 축으로 정규화하는 대안들이 있습니다.

- **Layer Normalization**: 각 샘플의 모든 채널에 대해 정규화 (배치 크기에 영향받지 않음, Transformer 계열에서 널리 사용)
- **Group Normalization**: 채널을 몇 개의 그룹으로 나눠 그룹별로 정규화 (작은 배치 크기의 이미지 모델에 유리)

### 8-6. 앙상블(Ensemble)과 전이 학습(Transfer Learning)

지금까지 다룬 기법들의 다음 단계로 이어지는 개념들입니다.

- **전이 학습**: ImageNet 등 대규모 데이터로 미리 학습된 모델을 가져와, 우리 데이터에 맞게 마지막 레이어만 새로 학습(fine-tuning)시키는 방법입니다. 데이터가 적을 때 특히 효과적입니다. [다음 글]({% post_url 2026-08-24-transfer-learning-resnet-vgg %})에서 ResNet-18과 VGG-19-BN을 직접 비교하며 자세히 다룹니다.
- **앙상블**: 여러 모델(또는 같은 모델의 서로 다른 체크포인트)의 예측을 종합해서 최종 예측을 내는 방법입니다. 단일 모델보다 일반적으로 더 안정적이고 높은 성능을 보입니다.

## 9. 핵심 정리 {#summary}

| 항목 | 핵심 내용 |
|---|---|
| **최적화 함수** | 깊은 네트워크에서는 Adam이나 Momentum 같은 고급 최적화 함수가 사실상 필수. 기본 SGD 대비 더 빠른 수렴과 안정적인 학습을 기대할 수 있음 |
| **과적합 방지 기법의 조합** | 드롭아웃, 배치 정규화, 데이터 증강을 함께 사용하면 시너지 효과 발생. 이번 실습에서는 70% → 89%로 정확도가 크게 개선됨 |
| **학습 시간과 성능의 균형** | 과적합 방지 기법을 쓰면 더 많은 에폭이 필요하지만, 최종 성능은 훨씬 우수함. 인내심을 갖고 충분히 학습시키는 것이 중요 |

**전체 흐름 한눈에 보기**

```
[이론]     신경망을 깊게 쌓는 이유 → CNN 아키텍처 설계 → 최적화 함수 선택
[문제 인식] 과적합이란 무엇인가 → 대응 전략 3가지 소개
[해결책 1] 드롭아웃 (train/eval 모드 차이)
[해결책 2] 배치 정규화 (Conv→BN→ReLU, 수식과 원리)
[해결책 3] 데이터 증강 (RandomHorizontalFlip, RandomErasing)
[검증]     개별 이미지 예측 확인 → 소프트맥스로 오분류 심층 분석
[다음 단계] Early Stopping, Weight Decay, LR Scheduler, 전이 학습, 앙상블
```

이론 설명 → 문제 제기 → 해결책 하나씩 대응하며 실험으로 검증 → 실패 사례 분석이라는 흐름을 따라가다 보면, 딥러닝 모델을 설계하고 과적합을 진단하며 여러 기법으로 대응하는 전체 사이클을 한 번에 이해할 수 있습니다.
