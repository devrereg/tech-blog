> 라이프오아시스에서 운영하는 서비스 **MAUM**의 **마케팅 프로모션 세팅 자동화** 기록이다. 매월 개발자가 코드로 작성·배포하던 프로모션을 Admin 기능으로 옮기고, 프로모션을 코드가 아닌 설정 데이터로 다루도록 바꾼 과정을 정리했다.

## 프로젝트 개요

- **회사 / 서비스**: 라이프오아시스 / MAUM
- **프로젝트명**: 마케팅 프로모션 세팅 자동화
- **일정**: 2024.05 (1개월)
- **기술 스택**: Next.js (React) · Spring Boot 3 (Kotlin) · MySQL · Redis · Kubernetes (K8s)

**설계 기준**

- 매월 반복되는 프로모션 세팅을 마케터가 개발자 없이 직접 운영하는 구조로 전환

## 아키텍처

![MAUM Admin 마케팅 프로모션 세팅 자동화 아키텍처 다이어그램](/assets/img/posts/maum-admin-automation/maum_admin_backoffice_architecture_2_promotion_automation.png)

*MAUM 마케팅 프로모션 세팅 자동화 구조 — 마케터가 Admin에서 등록한 프로모션 설정을 MySQL과 Redis에 저장하고, 서비스 API 서버는 Redis에서 설정을 읽어 적용한다.*

전체 작업은 **① 프로모션 구성 요소 정형화 → ② Admin 프로모션 관리 기능 개발 → ③ 설정 기반 조회** 순으로 진행했다.

**1. 프로모션 구성 요소 정형화**

- 프로모션을 기간·대상·보상·조건 등 여러 항목으로 이루어진 설정 스키마로 정의했다.

**2. Admin 프로모션 관리 기능 개발**

- Next.js(React) Admin 화면에서 입력한 프로모션을 Admin 서버(Spring Boot 3 + Kotlin, K8s)가 받아 MySQL에 저장한다.

**3. 설정 기반 조회**

- 서비스 API 서버는 요청이 들어올 때 Redis에서 프로모션 설정을 읽어 적용한다.

---

## 문제

### 1. 매월 반복되는 프로모션 세팅에 개발자 리소스 소모

- 매월 마케팅 프로모션이 열릴 때마다 개발자가 기간·대상·보상·조건 등의 로직을 직접 구현하고 배포했다. 한 건에 **2~3일**이 걸렸다.
- 프로모션마다 내용은 조금씩 달랐지만 구조는 거의 같아서, 매월 같은 작업을 반복하고 있었다.

### 2. 프로모션 변경이 개발 일정·배포에 종속

- 마케터가 프로모션 기간이나 조건을 바꾸려면 개발자 일정을 기다려야 했다.
- 급한 수정이나 조기 종료도 코드를 고쳐 배포해야 반영됐다.

---

## 해결

### 1. 프로모션을 코드가 아닌 설정 데이터로 전환

- 지난 프로모션들을 모아 공통 구조를 뽑고, 프로모션마다 따로 짜던 로직을 **설정 값을 읽어 동작하는 공통 로직** 하나로 바꿨다.
- 로직과 설정을 분리했기 때문에 프로모션 내용이 바뀌어도 **서버를 다시 배포하지 않는다**.

### 2. 프로모션 설정을 Redis에서 조회

- 프로모션 설정은 기간 중에는 바뀌지 않으면서, 기간 내내 유저 요청마다 조회된다.
- 그래서 설정을 **Redis에 저장**해 두고 서비스 API 서버가 Redis에서 읽도록 했다. 요청마다 MySQL을 조회하지 않는다.

### 3. Admin 프로모션 관리 기능 개발

- Admin에 프로모션 생성 / 수정 / 관리 화면을 만들어, 마케터가 프로모션을 직접 등록하고 변경하도록 했다.

---

## 결과

- 매월 프로모션 세팅에 쓰던 **2~3일의 개발 공수가 없어졌고**, 그 시간을 서비스 기능 개발에 썼다.

- 마케터가 개발자 일정과 관계없이 프로모션을 관리 한다.
