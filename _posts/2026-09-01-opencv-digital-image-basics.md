## 1. 학습 목표 {#goals}

컴퓨터 비전을 공부하는 첫걸음은 "컴퓨터가 영상을 어떻게 숫자로 이해하는가"를 아는 것입니다. 1주차의 목표는 다음 네 가지입니다.

1. **디지털 영상의 이해** — 디지털 영상의 개념과 데이터 표현 방식(행렬, 픽셀)
2. **색공간 마스터** — RGB, HSL, HSV 등 다양한 색공간의 이해와 상호 변환
3. **픽셀 연산 활용** — 밝기·대비 조정, 임계값 처리 등 픽셀 단위 연산
4. **히스토그램 분석** — 밝기 분포 분석, 정규화 및 평활화 기법

핵심을 먼저 말하면, 이 네 가지를 관통하는 축은 **"영상 = 0\~255 정수(uint8) 행렬"** 이라는 한 문장입니다.

## 2. 신호의 디지털화: 샘플링·양자화·인코딩 {#digitization}

컴퓨터는 세상을 있는 그대로 받아들이지 못합니다. 자연계의 소리나 빛처럼 끊어지지 않고 이어지는 **아날로그 신호(Analog)** 를, 0과 1로 표현되는 불연속적인 **디지털 신호(Digital)** 로 바꿔야만 저장하고 처리할 수 있습니다.

이 변환 과정은 다음 3단계로 이루어집니다.

| 단계 | 이름 | 하는 일 |
|---|---|---|
| ① | **샘플링 (Sampling)** | 연속 신호를 일정한 간격(시간/공간)으로 잘게 쪼개 표본을 추출 |
| ② | **양자화 (Quantization)** | 추출된 표본 값을 정해진 범위의 대표값(정수)으로 근사하여 매핑 |
| ③ | **인코딩 (Encoding)** | 양자화된 값을 컴퓨터가 처리할 수 있는 이진수(0과 1)로 변환·저장 |

![연속 아날로그 파형을 일정 간격으로 표본 추출(샘플링)하고, 각 표본을 정해진 정수 레벨로 반올림(양자화)한 뒤, 이진수로 저장(인코딩)하는 3단계 흐름도](/assets/img/posts/opencv-digital-image-basics/01_digitization.svg)

영상으로 치환하면, 샘플링은 "격자로 잘게 나누기(픽셀화)", 양자화는 "각 격자에 0\~255 사이의 밝기 값 부여하기"에 해당합니다.

### 얼마나 촘촘하게 샘플링해야 할까 — 나이퀴스트 레이트

샘플링에는 두 가지 상충하는 요구가 있습니다.

- **더 촘촘하게 추출한다** : 샘플링 레이트(Sampling Rate, Hz)가 클수록 원본과 유사해지지만(고해상도), 데이터 용량과 처리 비용이 커진다.
- **신호의 손실 없이 추출한다** : 손실 없이 원신호를 복원하기 위한 최소 샘플링 수를 **나이퀴스트 레이트(Nyquist Rate)** 라 한다.

$$F_s > 2 \times F_{max}$$

즉 샘플링 주파수는 신호에 담긴 최고 주파수의 2배보다 커야 합니다. 이 기준보다 낮게 샘플링하면 신호의 스펙트럼이 서로 겹쳐, 원신호를 정확히 복원할 수 없는 **에일리어싱(Aliasing)** 이 발생합니다. 영상에서는 축소·회전 시 나타나는 계단 현상이나 모아레 무늬가 대표적인 예입니다.

## 3. 색공간(Color Space) {#color-space}

**색공간**이란 색을 수치적으로 표현하기 위한 좌표계입니다. 사람 눈에는 사진 한 장으로 보이지만, 컴퓨터에게는 픽셀마다 숫자가 매겨진 거대한 행렬일 뿐이고, 이 숫자를 "어떻게 해석할 것인가"에 따라 색공간이 달라집니다.

![RGB·HSL·HSV 세 색공간을 비교한 그림. RGB는 빛의 삼원색 가산 혼합으로 장치 표준이지만 조명에 민감하고, HSL·HSV는 색상·채도를 밝기와 분리해 다루며 HSV가 조명 변화에 강해 컴퓨터 비전에 유리하다](/assets/img/posts/opencv-digital-image-basics/02_colorspace.svg)

| 색공간 | 구조 | 특징 |
|---|---|---|
| **RGB** (Red-Green-Blue) | 정육면체 | 빛의 삼원색을 조합하는 가산 혼합 방식. 모니터·카메라 등 디스플레이 장치의 표준 |
| **HSL** (Hue-Saturation-Lightness) | 이중원뿔(bi-cone) | 색상·채도·밝기로 구성, 인간의 색 인지 방식과 유사해 직관적 |
| **HSV** (Hue-Saturation-Value) | 원뿔(hexcone) | HSL과 유사하지만 명도(Value) 기준, 컴퓨터 비전의 색상 기반 분할에서 자주 활용 |

OpenCV에서 `cv2.cvtColor(img, cv2.COLOR_BGR2HSV)` 처럼 색공간 사이를 변환합니다. (OpenCV는 관례적으로 RGB가 아니라 **BGR** 순서로 채널을 저장한다는 점도 1주차에서 반드시 기억해 둘 함정입니다.)

### 왜 컴퓨터 비전에서는 HSV를 즐겨 쓸까

RGB는 조명이 바뀌면 R, G, B 세 값이 모두 함께 변해버려서 "같은 색"임을 인식하기가 어렵습니다. 반면 HSV는 **색상 정보(Hue)가 밝기(Value)와 분리**되어 있어서, 조명이 바뀌어도 H(색상) 값은 비교적 유지됩니다. 그래서 객체 추적, 피부색 검출, 특정 색상 영역 분리 같은 작업에서는 RGB보다 HSV가 훨씬 유리합니다.

## 4. 픽셀 연산 {#pixel-operations}

픽셀 연산은 0\~255 범위의 픽셀 값에 수학적 연산을 적용해 영상의 밝기·대비·색상을 조정하거나 합성하는 기법입니다. 크게 세 갈래로 나뉩니다.

- **산술/스칼라 연산** : 덧셈(밝게), 뺄셈(어둡게/차이), 가중합, 절댓값 차이 등
- **논리 연산 (Bitwise)** : AND, OR, XOR, NOT
- **마스크 연산 (ROI)** : 관심 영역만 골라서 처리

### ⭐ 모든 연산의 전제: uint8

OpenCV의 영상 데이터는 기본적으로 **uint8(8비트 부호 없는 정수)** 형식으로 저장됩니다.

- **unsigned** : 부호(+, −) 없음 → 음수 없이 0 이상만
- **8bit** : $2^8 = 256$가지 값 → **0\~255** 범위
- 0 = 완전 어두움(검정), 255 = 완전 밝음(흰색)

이 uint8이라는 자료형의 범위 제한(0\~255) 때문에, 픽셀 연산에서는 값이 범위를 벗어날 때 이를 처리해주는 규칙이 반드시 필요합니다.

### 덧셈/뺄셈: 포화(Saturation)와 클램핑(Clamping)

| 연산 | 함수 | 목적 | 범위를 벗어날 때 |
|---|---|---|---|
| 덧셈 | `cv2.add(src1, src2)` | 밝기 증가, 두 영상 합성 | 255 초과 시 **255로 고정(포화)** |
| 뺄셈 | `cv2.subtract(src1, src2)` | 밝기 감소, 두 영상 차이 계산 | 0 미만 시 **0으로 고정(클램핑)** |

![덧셈은 결과가 255를 넘으면 255에서 평평하게 포화되고, 뺄셈은 결과가 0 아래로 내려가면 0에서 멈추는 클램핑이 일어나는 것을 두 그래프로 비교](/assets/img/posts/opencv-digital-image-basics/03_pixel_ops.svg)

일반적인 numpy 연산에서는 256이 되면 0으로 순환(overflow)되지만, `cv2.add`/`cv2.subtract`는 이런 순환 없이 0\~255 범위 안으로 값을 강제로 고정해준다는 점이 핵심입니다.

```python
import numpy as np, cv2

a = np.full((1, 1), 250, dtype=np.uint8)
b = np.full((1, 1), 10,  dtype=np.uint8)

print(a + b)            # [[4]]     ← numpy: 260 → 오버플로로 순환
print(cv2.add(a, b))    # [[255]]   ← OpenCV: 255로 포화
```

### 가중합과 절댓값 차이

- **가중합 (`cv2.addWeighted`)** : 두 영상을 비율(투명도)에 맞게 섞는 연산. 블렌딩, 장면 전환(Transition) 효과에 사용.

  $$dst = src1 \times \alpha + src2 \times \beta + \gamma$$

  보통 $\alpha + \beta = 1$이 되도록 설정해 평균 밝기를 유지합니다.

- **절댓값 차이 (`cv2.absdiff`)** : 두 영상의 차이를 절댓값으로 계산. 단순 뺄셈은 결과가 음수면 0으로 잘려버리지만, 절댓값 차이는 변화량 자체를 양수로 보존합니다. 그래서 **이전 프레임과 현재 프레임의 변화를 감지**하는 데 쓰이며, CCTV의 움직임 감지(Motion Detection)가 대표적인 예입니다.

### 논리 연산 (Bitwise)

아래 "규칙"은 값이 0 또는 255인 **마스크(흑백 이미지) 기준** 설명입니다. 실제로는 비트 단위로 동작하므로, 0/255가 아닌 일반 픽셀 값에서는 비트 패턴에 따라 결과가 달라집니다.

| 연산 | 함수 | 규칙 (마스크 기준) | 용도 |
|---|---|---|---|
| AND | `cv2.bitwise_and()` | 두 값이 모두 0이 아닐 때만 유지 | 마스크 기반 영역 추출, 교집합 |
| OR | `cv2.bitwise_or()` | 하나라도 0이 아니면 켜짐 | 두 영상 합치기, 합집합 |
| XOR | `cv2.bitwise_xor()` | 두 값이 서로 다를 때만 켜짐 | 변화 감지, 차집합 강조 |
| NOT | `cv2.bitwise_not()` | 값을 반전 (0↔255) | 색상 반전, 마스크 뒤집기 |

![AND는 (1,1)에서만 켜지고, OR은 (0,0)만 꺼지며, XOR은 두 입력이 다른 (0,1)·(1,0)에서만 켜지는 것을 2×2 진리표로 표현](/assets/img/posts/opencv-digital-image-basics/04_logic_ops.svg)

### 마스크 연산 (ROI)

**마스크(Mask)** 는 uint8 흑백 이미지로, 픽셀 값이 0이면 '무시', 0이 아니면 '적용'을 의미합니다(입력 영상과 크기가 동일해야 함). 마스크를 다루는 작업은 보통 이런 흐름으로 이어집니다.

1. **생성** : `cv2.inRange()`(색상 범위 지정), `cv2.threshold()`(임계값 기준 이진화)
2. **도형** : `cv2.rectangle()`, `cv2.circle()`로 관심 영역을 직접 그려 지정
3. **적용** : `cv2.bitwise_and()`(ROI만 추출), `cv2.bitwise_not()`(영역 반전)
4. **후처리** : `cv2.inpaint()`(주변 색으로 복원), Morphology/Blur(노이즈 정리)

## 5. 히스토그램 분석 {#histogram}

영상의 밝기 분포(히스토그램)를 분석하면, 영상이 전반적으로 어두운지 밝은지, 대비가 뚜렷한지 흐릿한지를 한눈에 파악할 수 있습니다. 이를 개선하는 대표적인 두 기법이 **정규화**와 **평활화**입니다.

![좁은 범위에 몰려 있던 밝기 분포(Before)가 0~255 전 구간으로 넓게 펼쳐진 분포(After)로 바뀌면서 명암 대비가 살아나는 것을 두 히스토그램으로 비교](/assets/img/posts/opencv-digital-image-basics/05_histogram.svg)

- **정규화 (Normalization)** — 좁은 범위에 몰려 있는 픽셀 값 분포를 전체 범위(0\~255)로 늘려 펴는 과정. 현재 영상의 최솟값을 0, 최댓값을 255로 맞추고 나머지를 비율에 따라 선형 변환합니다.

  $$dst = \frac{src - min}{max - min} \times 255$$

  OpenCV에서는 `cv2.normalize(src, None, 0, 255, cv2.NORM_MINMAX)` 로 수행합니다.

- **평활화 (Equalization)** — 픽셀 값의 분포(빈도)까지 고려해 균등하게 재배치하는 기법. 단순히 범위만 늘리는 정규화보다 한 단계 더 나아가, 누적분포함수(CDF)를 이용해 몰려 있는 픽셀들을 통계적으로 재배치함으로써 전체 명암 분포를 고르게 만듭니다. `cv2.equalizeHist(gray)` 로 수행하며, 국소 대비를 살리려면 `cv2.createCLAHE()` 를 씁니다.

두 기법 모두 목적은 같습니다 — **명암 대비(Contrast)를 향상**시켜 흐릿한 영상을 또렷하게 만드는 것. 역광으로 피사체가 검게 나온 사진을 보정하거나, 안개 낀 풍경 사진을 선명하게 복원하는 데 실제로 활용됩니다.

## 6. 마무리 {#summary}

1주차에서 다룬 흐름을 한 줄로 정리하면 다음과 같습니다.

```
아날로그 신호
  → 디지털화 (샘플링 · 양자화 · 인코딩) → 0~255 픽셀 행렬
  → 색공간 해석 (RGB · HSL · HSV, CV에서는 조명에 강한 HSV 선호)
  → 픽셀 연산 (산술: 포화·클램핑 / 논리: AND·OR·XOR·NOT / 마스크: ROI)
  → 히스토그램 보정 (정규화 · 평활화로 명암 대비 향상)
```

**핵심 체크리스트**

- [ ] 디지털화는 샘플링 → 양자화 → 인코딩 3단계이며, 나이퀴스트 레이트($F_s > 2F_{max}$)보다 낮게 샘플링하면 에일리어싱이 생긴다
- [ ] 영상은 결국 uint8(0\~255) 정수 행렬이고, OpenCV는 채널을 BGR 순서로 저장한다
- [ ] 조명 변화에 강한 색상 기반 처리가 필요하면 RGB보다 HSV를 쓴다
- [ ] `cv2.add`/`cv2.subtract`는 numpy와 달리 오버플로 없이 255 포화·0 클램핑으로 값을 고정한다
- [ ] `cv2.absdiff`는 변화량을 양수로 보존해 프레임 간 움직임 감지에 쓰인다
- [ ] 마스크는 0/255 흑백 이미지이며, `bitwise_and`로 ROI만 남긴다
- [ ] 정규화는 값의 범위를, 평활화는 값의 분포까지 펴서 명암 대비를 높인다

반복적으로 등장한 **uint8(0\~255)** 이라는 자료형이 픽셀 연산의 포화/클램핑 처리, 마스크의 0/255 이진 표현 등 여러 개념을 관통하는 핵심 축이라는 점이 인상 깊었습니다. 다음 시간에는 이 개념들을 바탕으로 OpenCV 실습(임계값 처리, 컨투어, 필터링)을 이어갈 예정입니다.
