## 1. 필터 vs 기하학적 변환 {#filter-vs-transform}

영상 처리는 크게 두 갈래로 나눌 수 있습니다.

| 구분 | 무엇을 바꾸나 | 예시 |
|---|---|---|
| **필터 (Filter)** | 픽셀의 **값** | 블러, 엣지 검출, 노이즈 제거 |
| **기하학적 변환** | 픽셀의 **위치(좌표)** | 이동, 회전, 확대/축소, 아핀, 투시 |

이 글에서는 이 두 가지를 순서대로 훑어봅니다.

---

## 2. 필터(Filter)란? {#filter}

**정의**: 영상에서 각 픽셀의 값을 그 주변 값까지 고려하여, 수학적 연산을 통해 새로운 픽셀 값으로 계산하는 과정입니다.

**작동 방식**: 작은 행렬인 **커널(Kernel)** 을 영상 위로 슬라이딩시키며, 커널과 겹치는 영역의 픽셀 값을 연산해 새로운 중심 픽셀 값을 만들어냅니다. 이 핵심 연산을 **컨볼루션(Convolution)** 이라고 부르며, 수식으로는 다음과 같이 표현됩니다.

$$\text{New Pixel} = \Sigma(\text{Kernel} \times \text{Area})$$

![6×6 픽셀 값 행렬 위에 3×3 커널이 겹쳐 있고, 겹치는 9개 픽셀의 가중합(Σ(K × Area))이 오른쪽의 새 픽셀 하나로 매핑되는 컨볼루션 연산 개념도](/assets/img/posts/opencv-geometric-transformation/01_convolution.svg)

*커널이 이미지 위를 한 칸씩 이동하며, 겹치는 영역의 가중합으로 새 픽셀 값을 계산하는 과정*

### 필터의 목적과 활용

- **목적**: 영상의 특징(Edge, Blur, Sharpening)을 강조하거나 억제하고, 노이즈를 제거하거나 영상을 부드럽게 만듭니다.
- **활용 분야**: 딥러닝 기반 객체 인식의 전처리, 컴퓨터 비전의 코너 검출, 텍스처 분석 등

CNN의 합성곱도 결국 같은 연산입니다. 차이는 **커널 값을 사람이 설계하느냐(고전 필터), 학습으로 찾느냐(CNN)** 뿐입니다. 이 부분은 [CNN 합성곱 연산 완전 정리]({% post_url 2026-08-28-cnn-convolution-complete-guide %})에서 따로 다뤘습니다.

## 3. 필터의 종류 {#filter-types}

필터는 목적에 따라 크게 세 가지로 분류할 수 있습니다.

### 3-1. Smoothing / Blurring — 영상을 부드럽게

| 필터 | 특징 | OpenCV 함수 |
|---|---|---|
| 평균 (Average) | 커널 내 픽셀 값을 평균값으로 대체 | `cv2.blur()` |
| 가우시안 (Gaussian) | 중심에 가까울수록 가중치를 높게 두는 가우시안 분포 | `cv2.GaussianBlur()` |
| 중간값 (Median) | 픽셀들을 정렬해 중앙값 선택 (소금-후추 노이즈 특효) | `cv2.medianBlur()` |
| 양방향 (Bilateral) | 거리와 색상 차이를 모두 고려해 **엣지는 보존**하며 평균 | `cv2.bilateralFilter()` |

### 3-2. Edge Detection / Sharpening — 경계 검출과 선명화

| 필터 | 특징 | OpenCV 함수 |
|---|---|---|
| 소벨 (Sobel) | 1차 미분 기반, 수평/수직 방향성 있는 엣지 검출 | `cv2.Sobel()` |
| 라플라시안 (Laplacian) | 2차 미분 기반, 방향 구분 없이 전방위적 엣지 검출 | `cv2.Laplacian()` |
| 캐니 (Canny) | 노이즈 제거 + 그래디언트 + 히스테리시스 임계값의 단계적 검출 | `cv2.Canny()` |

### 3-3. 모폴로지(Morphology) — 형태 처리

| 필터 | 특징 | OpenCV 함수 |
|---|---|---|
| 침식 (Erosion) | 객체 외곽을 깎아냄 (작은 노이즈 제거, 영역 분리) | `cv2.erode()` |
| 팽창 (Dilation) | 객체 외곽을 확장 (구멍 메우기, 영역 연결) | `cv2.dilate()` |
| 열기 (Opening) | 침식 → 팽창 | `cv2.morphologyEx(img, cv2.MORPH_OPEN, k)` |
| 닫기 (Closing) | 팽창 → 침식 | `cv2.morphologyEx(img, cv2.MORPH_CLOSE, k)` |

#### 💡 열기(Open)와 닫기(Close), 헷갈리지 않는 법

이름 자체가 곧 연산 순서입니다.

- **OPEN = 침식 → 팽창** → 배경의 **작은 흰 점(노이즈)이 사라짐**
- **CLOSE = 팽창 → 침식** → 객체 내부의 **작은 구멍이 메워짐**

아래 다이어그램은 노이즈가 있는 원본과 구멍이 있는 원본에 각각 Open/Close를 적용했을 때, 중간 단계(침식→팽창, 팽창→침식)가 어떻게 다른 결과를 만드는지 보여줍니다.

![위 행은 MORPH_OPEN: 노이즈가 있는 원본을 침식해 객체가 작아지며 노이즈가 사라지고, 다시 팽창해 크기를 복원하되 노이즈는 제거된 상태. 아래 행은 MORPH_CLOSE: 구멍이 있는 원본을 팽창해 구멍을 메우고, 다시 침식해 크기를 복원하되 구멍은 메워진 상태](/assets/img/posts/opencv-geometric-transformation/04_morphology.svg)

*위: MORPH_OPEN — 침식 후 팽창하여 배경 노이즈 제거 / 아래: MORPH_CLOSE — 팽창 후 침식하여 내부 구멍 메움*

> **한 줄 요약**: OPEN = 깎아서(침식) 작은 것 없애기 / CLOSE = 채워서(팽창) 구멍 메우기

## 4. 영상의 기하학적 변환 {#geometric-transformation}

**정의**: 이미지의 좌표 $(x, y)$ 를 새로운 좌표 $(x', y')$ 로 매핑하는 과정.

모든 기하학적 변환은 다음 하나의 공식으로 통일해서 이해할 수 있습니다.

$$dst(x, y) = src(M \cdot [x, y, 1]^T)$$

여기서 `M` 은 **변환 행렬(Transformation Matrix)** 이며, $[x, y, 1]^T$ 는 좌표를 **동차좌표(Homogeneous Coordinate)** 로 표현한 것입니다. 즉, **"모든 기하학적 변환 = 행렬 M을 좌표에 곱하는 것"** 으로 이해하면 됩니다.

### OpenCV의 관점: "액자는 고정, 그림만 조작"

OpenCV는 이미지의 **액자(Canvas, 크기/틀)** 는 고정하고, 그 안에 담긴 **그림(Content, 실제 픽셀 내용)** 만 조작하는 방식으로 변환을 수행합니다. 그래서 회전이나 확대를 하면 이미지의 일부가 캔버스 밖으로 잘려나가는 경우가 생길 수 있습니다.

### 5가지 주요 변환 유형

아래는 원본(점선)에서 각 변환을 적용했을 때(실선) 도형이 어떻게 달라지는지를 정리한 것입니다.

![원본 정사각형(점선)에 다섯 가지 변환을 적용한 결과(실선) 비교. 이동은 위치만, 회전은 중심점 기준 각도만, 확대/축소는 크기 비율만 바뀌고, 아핀은 평행사변형으로 기울어지지만 마주보는 변은 여전히 평행](/assets/img/posts/opencv-geometric-transformation/02_transforms.svg)

| 변환 | 특징 |
|---|---|
| 이동 (Translation) | 위치만 변경 (크기·각도 유지) |
| 회전 (Rotation) | 중심점 기준 각도 변경 |
| 확대/축소 (Scaling) | 크기 비율 변경 |
| 아핀 (Affine) | 평행선 유지 (직사각형 → 평행사변형) |
| 투시 (Perspective) | 평행성이 깨지며 소실점에서 만남 (직사각형 → 사다리꼴) |

## 5. 회전 (Rotation) {#rotation}

**정의**: 영상을 기준점(주로 중심)을 중심으로 일정 각도만큼 돌려서 새 좌표로 변환하는 것.
**목적**: 물체의 방향 변화, 데이터 증강(Augmentation), 기하학적 보정

```python
cv2.getRotationMatrix2D(중심점, 각도, 스케일)
```

이 함수는 이름은 "회전"이지만 **회전 + 스케일링을 동시에** 처리할 수 있습니다.

원점을 중심으로 한 순수 회전은 다음과 같습니다.

$$\begin{bmatrix} x' \\ y' \end{bmatrix} = \begin{bmatrix} \cos\theta & -\sin\theta \\ \sin\theta & \cos\theta \end{bmatrix} \begin{bmatrix} x \\ y \end{bmatrix}$$

그런데 우리가 원하는 건 원점이 아니라 **중심점 $(c_x, c_y)$ 기준 회전**입니다. 그래서 실제로는 "중심을 원점으로 옮기고 $(-c_x, -c_y)$ → 스케일 $\alpha$ 를 곱해 돌리고 → 다시 제자리로 되돌리는 $(+c_x, +c_y)$" 3단계를 하나로 합친 행렬이 필요합니다. 이 되돌리는 성분이 **이동(translation) 열**로 남기 때문에, `getRotationMatrix2D()` 가 반환하는 것은 2×2가 아니라 **2×3 행렬**입니다.

$$M = \begin{bmatrix} \alpha & \beta & (1-\alpha)\,c_x - \beta\,c_y \\ -\beta & \alpha & \beta\,c_x + (1-\alpha)\,c_y \end{bmatrix}, \quad \alpha = s\cos\theta,\ \ \beta = s\sin\theta$$

세 번째 열이 바로 "중심 기준으로 돌리기 위한 보정 이동량"이고, 그래서 이 행렬은 그대로 `cv2.warpAffine()` 에 넣을 수 있습니다.

**주의할 점 3가지**

1. 반시계 방향이 양수(+) 각도입니다. 단, 영상 좌표계는 y축이 아래를 향하므로 화면상으로는 시계 방향으로 도는 것처럼 보입니다.
2. 회전 후 모서리가 캔버스를 벗어나 **잘리는 영역**이 생길 수 있습니다.
3. 회전 중심이 원점이 아니므로, 위에서 본 것처럼 반환 행렬에는 이동 성분이 함께 들어 있습니다.

```python
M = cv2.getRotationMatrix2D(center=(w/2, h/2), angle=45, scale=1.0)
rotated = cv2.warpAffine(img, M, (w, h))
```

## 6. 확대와 축소 (Scaling) {#scaling}

**정의**: 영상의 좌표를 일정 비율로 늘리거나 줄이는 변환.
**목적**: 해상도 변화, 데이터 증강, 객체 크기 보정

$$\begin{bmatrix} x' \\ y' \end{bmatrix} = \begin{bmatrix} s_x & 0 \\ 0 & s_y \end{bmatrix} \begin{bmatrix} x \\ y \end{bmatrix}$$

- $s_x > 1$: 가로 확대 / $0 < s_x < 1$: 가로 축소 (세로도 동일 원리)

### 왜 보간(Interpolation)이 필요한가?

확대·축소는 좌표 개수 자체가 바뀌기 때문에, **빈 공간을 채우거나(확대) 여러 픽셀을 하나로 합치는(축소)** 보간 과정이 필수적입니다.

| 상수(Flag) | 특징 | 속도 | 권장 용도 |
|---|---|---|---|
| `INTER_NEAREST` | 가장 가까운 이웃 픽셀 (계단현상) | 매우 빠름 | 속도 최우선 |
| `INTER_LINEAR` | 양선형 보간 (**기본값**) | 빠름 | 일반적인 경우 |
| `INTER_CUBIC` | 3차 스플라인 (선명함) | 보통 | **확대**할 때 |
| `INTER_AREA` | 픽셀 영역 재샘플링 | 빠름 | **축소**할 때 |

```python
# 확대할 때
enlarged = cv2.resize(img, None, fx=2.0, fy=2.0, interpolation=cv2.INTER_CUBIC)

# 축소할 때
shrunk = cv2.resize(img, None, fx=0.5, fy=0.5, interpolation=cv2.INTER_AREA)
```

> 1주차에서 다룬 **에일리어싱**이 여기서 다시 등장합니다. 축소는 샘플 수를 줄이는 작업이라 계단 현상·모아레가 생기기 쉬운데, `INTER_AREA` 는 영역 평균으로 재샘플링하므로 이를 완화해 줍니다.

## 7. Affine 변환 {#affine}

**정의**: 2D 평면상의 점을 선형 변환(확대/축소, 회전, 전단)과 평행 이동을 결합하여 매핑하는 방식.

**핵심 성질 두 가지**

- **평행성 유지**: 변환 전 평행선은 변환 후에도 평행 유지 (직사각형 → 평행사변형)
- **직선 보존**: 직선은 변환 후에도 직선

앞서 배운 이동, 회전, 확대/축소는 사실 아핀 변환의 **특수한 경우**입니다. 아핀 변환은 여기에 **전단(Shear)** 까지 더한, 더 넓은 범주의 변환입니다.

$$\begin{bmatrix} x' \\ y' \end{bmatrix} = \begin{bmatrix} a_{11} & a_{12} & t_x \\ a_{21} & a_{22} & t_y \end{bmatrix} \begin{bmatrix} x \\ y \\ 1 \end{bmatrix}$$

- $a_{11}, a_{12}, a_{21}, a_{22}$: 선형 변환 계수 (회전, 확대, 기울임)
- $t_x, t_y$: 평행 이동

### 왜 3개의 점만 있으면 될까?

2×3 행렬의 미지수는 6개($a_{11}, a_{12}, a_{21}, a_{22}, t_x, t_y$)입니다. 점 하나당 $(x, y)$ 대응관계가 방정식 2개를 만들어내므로, **3개의 점 × 2개 방정식 = 6개 방정식**으로 정확히 풀립니다.

```python
# 변환 전 3개의 점과 변환 후 3개의 점 필요
pts1 = np.float32([[50,50], [200,50], [50,200]])
pts2 = np.float32([[10,100], [200,50], [100,250]])

# 2x3 변환 행렬 계산
M = cv2.getAffineTransform(pts1, pts2)

# Affine 변환 적용
dst = cv2.warpAffine(img, M, (w, h))
```

**활용**: 이미지 정렬, 문서 스캔 보정(단순), 객체 자세 보정

## 8. Perspective 변환 {#perspective}

**정의**: 원근감을 반영하여 직선의 평행성이 깨지는 투시 변환 (Homography).

투시 변환은 **한 평면을 다른 평면으로 매핑하는 사영변환(2D → 2D)** 입니다. 일반적인 3D 물체를 2D로 투영하는 것이 아니라, *평면인 대상*(문서, 바닥, 벽면 등)이 카메라 시점에 따라 어떻게 찌그러져 보이는지를 모델링합니다 — 그래서 뒤에 나오는 문서 스캔 보정이 정확히 이 경우에 해당합니다. 직선은 그대로 직선으로 유지되지만, 아핀 변환과 달리 **평행선은 유지되지 않습니다.**

![왼쪽 아핀 변환: 직사각형이 평행사변형으로 기울어져도 빨간색으로 표시된 위·아래 변은 여전히 평행. 오른쪽 투시 변환: 직사각형이 사다리꼴로 바뀌면서 두 옆변을 연장한 빨간 점선이 아래쪽 소실점(Vanishing Point) 한 곳에서 만남](/assets/img/posts/opencv-geometric-transformation/03_affine_vs_perspective.svg)

*아핀 변환은 평행선(빨간 선)이 변환 후에도 평행을 유지하지만, 투시 변환에서는 평행선이 소실점(Vanishing Point)에서 만납니다.*

### 아핀 vs 투시 비교

| 구분 | 아핀(Affine) | 투시(Perspective) |
|---|---|---|
| 행렬 크기 | 2×3 | 3×3 |
| 자유도 | 6 | 8 |
| 필요한 점 | 3개 | 4개 |
| 마지막 행 | 고정 [0, 0, 1] | 가변 [h₃₁, h₃₂, h₃₃] |
| 정규화 필요 여부 | 불필요 | **필요** |
| 평행선 | 유지 | 소실점에서 만남 |
| 결과 도형 | 평행사변형 | 사다리꼴 |

### 변환 행렬과 정규화

$$\begin{bmatrix} x' \\ y' \\ w' \end{bmatrix} = \begin{bmatrix} h_{11} & h_{12} & h_{13} \\ h_{21} & h_{22} & h_{23} \\ h_{31} & h_{32} & h_{33} \end{bmatrix} \begin{bmatrix} x \\ y \\ 1 \end{bmatrix}$$

아핀 행렬과 달리 마지막 행 $[h_{31}, h_{32}, h_{33}]$ 이 고정되어 있지 않습니다. 이 성분이 바로 **원근 왜곡**을 담당합니다. 계산 결과로 바로 $(x', y')$ 가 나오는 것이 아니라, 먼저 $(X, Y, w')$ 가 나오고 이를 $w'$ 으로 나누는 **정규화** 과정이 필요합니다.

$$x' = \frac{X}{w'}, \quad y' = \frac{Y}{w'}$$

### 실전 활용: 문서 스캔 보정

핸드폰 카메라의 "문서 스캔" 기능이 대표적인 예시입니다. 비스듬히 찍힌 문서(사다리꼴)를 4개의 점을 지정해 반듯한 직사각형으로 펴줍니다.

```python
# 투시 변환 (4점, 3x3 행렬)
pts1 = np.float32([[좌상], [우상], [우하], [좌하]])  # 입력 4점
pts2 = np.float32([[0,0], [w,0], [w,h], [0,h]])      # 출력 4점 (반듯한 직사각형)
M = cv2.getPerspectiveTransform(pts1, pts2)
dst = cv2.warpPerspective(img, M, (w, h))
```

> ⚠️ **실무 팁**: 입력 4개 점의 순서(좌상 → 우상 → 우하 → 좌하)가 출력 좌표의 순서와 반드시 일치해야 이미지가 뒤집히지 않습니다.

## 9. 실무 적용 팁 {#tips}

1. **커널 크기는 홀수(3, 5, 7…)** 를 사용합니다. 짝수는 정확한 중심 픽셀이 없어 연산 결과를 어디에 넣을지 애매해지기 때문입니다. 커널이 클수록 블러링 효과가 강해집니다.
2. **보간법 선택**: 속도가 중요하면 `LINEAR`, 품질이 중요하면 `CUBIC`. 다만 **축소할 때는 `AREA`** 가 더 적합합니다 (에일리어싱 감소).
3. **데이터 타입 주의**: 필터·변환 연산 중 음수나 255 초과 값이 나올 수 있으므로, 연산 전 `float32` 로 변환하고 연산 후 `np.clip()` 으로 0\~255 범위로 잘라낸 뒤 다시 `uint8` 로 변환해야 합니다.

```python
img_float = img.astype(np.float32)
# ... 연산 수행 ...
result = np.clip(result, 0, 255).astype(np.uint8)
```

## 10. 마무리 {#summary}

오늘 배운 내용을 한 문장으로 정리하면 다음과 같습니다.

> 영상 처리는 **픽셀 값을 바꾸는 필터**와 **픽셀 위치를 바꾸는 기하학적 변환**으로 나뉘고, 후자는 전부 하나의 행렬 공식 $dst = M \cdot [x, y, 1]^T$ 으로 통일되며, **이동/회전/스케일 ⊂ 아핀 ⊂ 투시** 순으로 자유도가 확장되는 구조다.

| 변환 | 행렬 크기 | 필요한 점 | 평행선 | OpenCV 함수 |
|---|---|---|---|---|
| 이동/회전/스케일 | 2×3 (특수형) | - | 유지 | `getRotationMatrix2D`, `resize` |
| 아핀 | 2×3 | 3개 | 유지 | `getAffineTransform` |
| 투시 | 3×3 | 4개 | 깨짐(소실점) | `getPerspectiveTransform` |

**핵심 체크리스트**

- [ ] 필터는 픽셀의 **값**을, 기하학적 변환은 픽셀의 **좌표**를 바꾼다
- [ ] 컨볼루션은 커널과 겹치는 영역의 가중합이며, 커널 크기는 홀수를 쓴다
- [ ] 모폴로지 OPEN(침식→팽창)은 배경 노이즈 제거, CLOSE(팽창→침식)는 내부 구멍 메우기
- [ ] 모든 기하학적 변환은 $dst = M \cdot [x, y, 1]^T$ 하나로 통일된다
- [ ] `getRotationMatrix2D()` 는 이동 성분까지 포함한 2×3 행렬을 반환한다
- [ ] 확대는 `INTER_CUBIC`, 축소는 `INTER_AREA` 가 유리하다
- [ ] 아핀은 6자유도·3점·평행선 유지, 투시는 8자유도·4점·평행선이 소실점에서 만남
- [ ] 투시 변환은 결과 $(X, Y, w')$ 를 $w'$ 으로 나누는 정규화가 필수다

이 구조를 이해하고 나면, OpenCV의 기하학적 변환 함수들이 왜 그런 파라미터를 요구하는지, 그리고 각 변환이 언제 필요한지 훨씬 명확하게 그려집니다. 다음 시간에는 이 변환들을 컨투어 검출·특징점 매칭과 엮어 실습할 예정입니다.
